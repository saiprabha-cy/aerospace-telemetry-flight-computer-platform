03 / ENGINEERING

Designed as a verification chain, not a single script.

The project deliberately separates embedded implementation, numerical modeling and independent verification so a failure in one representation can be detected by another.

Embedded

STM32 Flight Computer

STM32F446RETx firmware written in modular C using STM32 HAL, STM32CubeMX/CubeIDE and ARM GCC. The scheduler executes sensor update, timestamping, health checks, mission logic, packet construction and UART transmission.

Telemetry

Binary Packet Engineering

A fixed 22-byte frame carries synchronization, version, sequence, timestamp, scaled physical values, status and CRC16. The layout is compact, deterministic and independently decoded in Python.

Simulation

MATLAB + Simulink

MATLAB generates a deterministic 60-second flight-state sequence. Simulink executes a fixed-step 0.1-second model for block-level health and flight-computer behavior.

Reference model

OpenRocket

A deliberately small reference rocket provides independent trajectory data. The CSV is cleaned before being converted into MATLAB timeseries and injected into Simulink.

Independent test

Python Verification

The host checker reconstructs packet fields and recalculates CRC independently of the firmware implementation, reducing the chance that the same bug is repeated in both producer and verifier.

Engineering principle

Cross-Validation

Results are compared across representations rather than trusted because one program returned a plausible number. This is the core engineering pattern demonstrated by ATFIDP.

Engineering boundary: ATFIDP is a software-first development and verification platform. It is not flight-qualified avionics and does not claim physical sensor validation, physical UART validation, flight testing, radiation assurance, or production timing qualification.

Trajectory note

Small reference rocket by design

The OpenRocket case is intentionally small and is used to exercise the CSV → MATLAB → Simulink integration path. Its approximately 1.98-second flight and 2.15 m apogee should not be interpreted as a realistic launch-vehicle envelope.

05 / ENGINEERING LOG

What broke — and what was changed.

The engineering value is in the debugging trail as much as the final green checks.

MATLAB / namespace
Variable shadowed the Simulink sim() function.

A loaded variable named sim caused sim(model_name) to resolve incorrectly. The variable was renamed to sim_data, restoring the intended function call.

OPENROCKET / DATA
Raw trajectory contained invalid rows.

The reference CSV contained 88 raw samples, including 9 invalid/non-finite rows. A preprocessing step removed those rows before creating MATLAB timeseries, leaving 79 valid samples for cross-validation.

INTEGRATION / ALIGN
Trajectory data needed explicit time alignment.

The OpenRocket output was cleaned and converted into explicit time-series channels before Simulink execution. This made the reference-data path reproducible rather than relying on implicit data interpretation.

TELEMETRY / CRC
Packet correctness was checked independently.

The reference 22-byte packet produced CRC 0x1318. The Python verifier independently decoded the fields and recalculated the same CRC, producing a PASS result.
